# 内装・採光の一括比較

既存の検証済みUEプロジェクトから、日時×仕上げの組み合わせを順番に撮影して、ローカルで開けるHTML一覧を作ります。UEを手動操作して撮影条件を揃える手間を減らすための機能です。

```powershell
python scripts/compare-unreal-studies.py --engine 'C:/Program Files/Epic Games/UE_5.8' --project build/ue-detail-v3 --cache '../../ddc' --output build/comparison-guest-v1
```

出力先は新しいフォルダにします。終了後の`index.html`をブラウザで開くと、同じ日時の仕上げ違いが並びます。画像をクリックすると原寸表示、撮影条件のリンクで日時・方位・高度・視点・露出のJSONを確認できます。サーバーやインターネット接続は不要です。

`--note '実敷地とは無関係のサンプル条件です。'`のように、比較に使った条件の説明を指定できます。注記は一覧の冒頭と比較JSONに保存します。

既定ではプロジェクト内の`sun-cases.json`の撮影可能な日時すべてと、natural/warmの2案を使います。日時を絞る場合は`--sun-cases 0 1`、仕上げを絞る場合は`--variants natural`を指定します。番号は0始まりです。夜間等の撮影対象外ケースは既定では除外し、明示指定された場合はエラーにします。1回につき最大24枚です。

元の建物・床材・家具・周辺物はそのプロジェクトの内容です。実敷地の日時を使いたい場合は、先にローカルの所在地・真北から太陽ケースを作り、UEプロジェクトを生成してください。既存の動作確認プロジェクトに入っている夏・冬の日時はサンプル地点であり、実敷地の条件ではありません。

## 比較条件の検証

- 太陽方向と日時の記録が指定ケースに一致すること。
- 仕上げが指定案に一致し、全画像のカメラ・光源強度・露出が同じであること。
- 材質設定、床材のシェーダー、周辺設定、画像寸法、レイトレーシング状態が比較間で変わらないこと。
- 撮影前後で生成アセット・レベル・比較設定のハッシュが変わらないこと。
- 各画像と条件ファイルのハッシュが撮影レポートに一致すること。

画像生成には既存の`capture-unreal-study.py`を使います。1枚ごとにエディタを起動するため、数分以上かかります。撮影中に同じプロジェクトを別のエディタで編集しないでください。

途中で失敗した場合は`comparison.json`を`status:failed`として残し、完成した比較一覧は作りません。成功済み画像は残ります。再実行には新しい出力フォルダを指定します。自動再開・古い画像の再利用はありません。撮影元プロジェクトのSavedにも元画像を残し、上書き衝突を避けるため各バッチに固有の名前を付けます。

## 保管と制約

出力はworktreeの`build/`内に限定します。画像・条件・ハッシュ一覧を含む`comparison.json`とHTMLはローカル成果物です。日時と角度から地域を推測できるため、公開Gitに追加しません。

仮材質による見え方の比較です。位置・方位が確認済みでも、ガラス透過率・天候・室内照度が校正されたことにはなりません。ゲストLDKのキッチン・冷蔵庫の正面方向は引き続き確認待ちです。
