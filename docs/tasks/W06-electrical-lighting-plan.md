# W06 電気設備と夜間照明比較 — 事前計画

2026-09-09：現行実装を照合し、[詳細仕様W06（READY）](W06-electrical-lighting.md)へ具体化しました。実装時は詳細仕様を優先します。

状態：DRAFT。2026-09-09作成。W05受入時に見直してREADYへ移します。

## 到達する成果

Three.jsで検討した照明器具の位置がUEの光源へつながり、ゲストLDKで点灯組合せ・色温度・明るさを歩いて比較できます。昼の採光と夜の照明を同じ内装上で検討する、最初の実用到達点です。

## 既存の土台と設計対象

既存electrical配置/カタログとThree.jsの編集・書出しを使います。器具の寸法/配置IDを正本にし、UE内だけの独立した配置は作りません。W04の面別仕上げ/案保存、W05の環境と比較条件の記録を再利用します。

参照：dataのelectrical関連JSON、tests/validate_electrical.py、scripts/build-web-data.mjs、Three.jsの設備編集、Blender/UE生成器、状態保存コード。フィールド名・灯具数・既存の親参照は着手前に現行データから確定します。

## まとめて実装する範囲

1. 設備種類を整理し、照明器具だけを光源として生成します。コンセントやスイッチを発光器具にはしません。配線設計そのものを照明シミュレーションと混同しません。
2. 器具ID→UE光源を対応させ、位置・向き・設置高さと光源中心を明示します。天井付け/壁付けなどの取付基準と、家具へ付随する器具がある場合の親ID＋相対位置を決めます。孤立参照は既存の事前確認へ接続します。
3. 光束、色温度、配光、調光率を型/配置/案のどこで持つか固定します。器具仕様はカタログ、点灯/調光は案、位置は共有配置という境界を基本にします。単位変換と二重倍率を避けます。
4. 利用できる実器具仕様/IESがあれば採用し、なければ明示した仮配光を使います。仮仕様も編集・比較でき、採用品が決まったときIDを維持して差し替えられるようにします。
5. 消灯/全灯/必要なグループの点灯と調光を操作でき、夜間環境で比較します。昼間専用の太陽高度/最低照度バリデータを夜へ無理に流用せず、太陽無効を明示した状態契約にします。W05の昼条件は後方互換で読みます。
6. 名前付き案・A/B・内覧保存・再生成に点灯条件を含めます。A/Bで照明を比較する場合は視点・露出・外部環境・仕上げを固定します。仕上げ比較との切替対象をUIで明示します。

## 入力と範囲

最初の確認対象はゲストLDKの代表器具です。採用品番が未確定でも仮仕様で機能を完成させます。初回に光源対応できる設備種類を表にし、未対応を黙って無視しません。すべての器具のメーカー資料収集、施工用の回路/負荷計算、照度の規格適合判定は対象外です。

## 完了条件・軽い検証

- 代表器具の位置変更を共有JSONへ反映して再生成すると、UE光源が正しい位置/向きへ追従します。
- 代表の点灯/消灯・色温度/調光の差が見え、他のグループへ意図しない影響がありません。
- 夜間の2案を同条件で比較でき、再起動/再生成後も面別仕上げと点灯条件を保持します。
- 削除器具への参照または不正な光源値を1例案内します。仮仕様が明示されます。

## 着手時に見直すこと

W05の昼/夜条件形式、既存設備に実際に必要な親追従、代表器具のデータ有無を確認します。原則一括です。配光データの取得待ちだけなら仮配光を使い、工程を止めません。異なる器具方式で生成経路が根本的に分かれる場合に限り範囲を再判断します。

規模見込み：大。状態契約・光源変換・操作の接続が主な作業です。成果物は器具対応/確度表、点灯操作、代表夜間比較、W06-reportとレビュー束です。
