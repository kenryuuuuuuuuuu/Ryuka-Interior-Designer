- door-bindings.json：同じ葉のopenYawDeltaDegは **85度**。
- エディタのapply_state、UEインポート、Blender生成は、open=trueならbindingsの85度を使います。エディタ検証も85±1度を成功条件にしています。

また、部分開放の計算は現在の葉位置から毎回行われ、SetFinish/SetSun等もApplyConditionsを呼びます。75度から85度へ再試行すると、Fracは「残り10度のうち進める割合」ですが、通行判定は85×Fracを最終角として扱います。既に通行可能な開扉を維持するだけの操作でも、拒否や角度変化が起きる経路です。この経路はレビュー側でUE実行再現していませんが、現在姿勢に依存した再計算と角度計算の不一致をコードで確認しています。保存済み85度の葉を読み込んだ場合はFrom==Toで干渉確認を省略するため、内覧に戻せば常に75度へ直るとも言えません。

### 修正方針

今回のbool形式を維持する最小の方法は、**固定壁に対して安全な開ポーズを生成条件として一度解決し、同じ値を全consumerで使う**ことです。door-002の制限角も共有bindingsへ反映し、Blender/UEエディタ/内覧が同じ閉・開transformを適用します。寸法の正本は変更しません。仮の取付条件や角度補足を用いる場合は根拠・確度を記録します。

人・家具等のためにその共通開ポーズへ移動できない場合は操作を拒否し、open=trueの意味をその場の障害物で変えません。これなら新たな開角編集UIや保存schemaの拡張は不要です。別方式を選ぶ場合も、実開ポーズの保存・旧案互換・全表示経路の一致まで一括で成立させてください。

同じ状態の再適用では葉を動かさず、仕上げ/太陽の変更が開扉状態を再解釈しないようにします。干渉判定は状態が実際に変わる開閉動作に適用します。
