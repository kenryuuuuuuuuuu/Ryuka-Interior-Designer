## 設計契約

### 歩行と入力

対象はroom-1f-06だけです。既存の身体半径25cm・高さ176cm、名目目線160cm、速度120cm/sを既定値として維持します。通り抜けのため家具を移動/縮小しません。WASDは視点の水平向きに沿い、斜め歩きで速くならないこと。キーを離すと停止し、Tabでカーソル解放中は視点と移動を止めます。復帰時に大きく視点が飛ばないこと。上下視点は±80度以内とし、床抜け・壁抜けを許しません。

現行Tickの `Safe(Next)` は行き先が壁に近いだけで移動入力全体を拒否します。壁際の斜め移動が固まる場合、床と衝突を扱うCharacterMovementのスイープ/滑りを活かして修正してください。ポリゴン外への移動防止は維持し、衝突なしのSetActorLocation連打や、移動後の境界未確認を回避策にしません。処理順・慣性・低fpsでも確認します。正常に動く箇所は書き換えません。

### 保存・復帰

`study-state.json` と `Saved/walkthrough-state.json` の最新選択、同時刻は既存のstudy優先、スキーマ1.0.0、smoke専用ファイル分離を維持します。ユーザー保存の形式を勝手に変えません。

復帰は必要な設定・部屋ID・数値・カメラを検証してから適用します。JSON破損、必須フィールド欠落、別部屋、範囲外、材質未取得でクラッシュしないこと。新しい保存が無効なら有効な基準状態へ戻し、その事実を表示します。両方無効なら移動を開始せず理由を表示し、ファイルを上書きしません。

保存位置が家具と重なる場合は既存の安全候補探索で同室内へ移し、移動したことを表示します。候補なしなら移動停止。復帰中に材質/太陽だけが部分適用されないよう、変更前に検証します。

現行RestoreはlensMmをEyeの画角へ反映していません。既存契約（36mm幅、lensMm=18/tan(FOV/2)）の逆変換で復帰し、固定の80度で上書きしないでください。Python側の許容範囲を確認し、float32丸めを考慮して往復を検証します。カメラZは歩行用の床/目線へ補正する既存仕様なので、固定画像の任意高さと完全一致とはしません。X/Yと向き・画角、条件を検証します。

F5の書込み失敗を成功表示にせず既存ファイルを保護します。仕上げ/太陽変更失敗時には状態JSONと画面が食い違わないようにします。手動太陽へ切替成功時のみsolar日時由来の記録を解除します。

### 操作案内

HUDを日本語で読める案内にします。操作キー、現在の仕上げ、太陽が仮条件であること、保存/復帰の結果、復帰できない理由を短く表示します。日本語フォントの実描画を確認し、四角い代替文字で完了扱いにしません。OS固有フォント絶対パスに依存せず、UE標準で対応可能か確認し、追加アセットが必要なら利用条件と再生成時の配置を記録します。新しいメニュー基盤や外部UIライブラリは不要です。

## 実装・検証順序

1. 現行版の手動入力をまず確認し、実際の不具合と上記コード上の不足を記録します。OSへの入力が使えない環境なら施主に短い確認手順を渡し、未実行を明示します。関数直接呼出しは実入力の代用にしません。
2. 保存/復帰の検証と画角、移動、HUDを小さなコミット単位で修正します。生成プロジェクトに現在のコードを反映してから実行します。
3. 新しいbuild出力を使って状態の異常系を試します。施主のSavedファイルをテスト用に改変しません。必要な自動検証の入口はsmoke専用に限定します。
4. 下記を確認し、正本から新出力への一括refreshも実行します。家具移動による衝突位置復帰はコピーした入力/専用テスト環境で行い、正本の配置変更を残しません。
