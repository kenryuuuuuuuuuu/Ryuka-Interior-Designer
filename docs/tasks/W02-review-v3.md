## A / 必須：バックアップ復元失敗を扱う

Walkthrough.cpp:237ではバックアップを元に戻すMoveの戻り値を無視しています。復元が失敗するとPathなし/Backupありとなりますが、F9/起動はBackupを参照せず基準状態へ戻ります。後続のF5もPathなしを「初回保存」と扱い、さらに次の上書き保存で既存Backupを削除し得ます。旧保存を回復可能な形で保持する、という契約が最後まで成立していません。

今回の修正範囲：

1. 復元成否を確認し、復元失敗時はバックアップを残して「保存の復旧が必要」と明示します。
2. 未復旧Backupがある間は通常保存へ進まず、そのBackupを削除/上書きしません。少なくともPathなし/Backupありを初回保存扱いにしないこと。
3. 起動/F9でも復旧待ちを検出します。自動復旧を行うか、バックアップの場所と復旧手順を文書で案内するかは実装者に任せますが、基準状態へ黙って戻って保存を重ねる挙動は禁止です。自動復旧が再失敗してもBackupを保持します。
4. 検証用に「置換失敗＋バックアップ復元失敗」を発生させ、Backupハッシュ保持→再F5でも保持→再起動でも認識→障害解除後に旧保存を復旧、まで確認します。

停電耐性や汎用履歴管理は追加しません。単純な復旧待ち状態で十分です。

## B / 必須：2回の補正失敗後は通常操作へ進めない

Walkthrough.cpp:325-330。2回ともSafeでない場合に安全位置を更新しない点は正しいですが、bReadyを維持して後続のAddMovementInputへ進むため、安全でない位置のまま移動とF5保存が継続できます。次フレームでの再試行は安全な復帰の保証ではありません。

今回の最小方針は「復帰不能なら操作停止」です。最終Safe判定失敗時はStopMovementImmediately、DisableMovement、bReady=falseとして以後の移動/保存を止め、HUDに「安全な位置へ戻れません。F9で復元してください」等を表示してください。F9のRestoreがSafeな開始点を確保できた場合のみ再開します。無条件テレポートは復活させません。この異常停止は通常の部屋外移動を許可するものではなく、補正不能の明示的なエラー状態です。

独立した検証で(1)最初の補正失敗→2回目成功、(2)両方失敗→操作停止、(3)F9で安全点へ復帰、を直接通してください。最終座標・Safe結果・分岐到達・bReady/移動状態・F5でファイルが変わらないことを記録します。狭所で長く歩くだけでは当該分岐の検証になりません。
