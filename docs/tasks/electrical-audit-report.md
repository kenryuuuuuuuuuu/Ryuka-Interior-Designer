# 電気設備 監査レポートと配置草案（2026-09-14）

施主の指示（2026-09-14）に基づく、現状 `data/electrical.json` の監査と、一般的な住宅電気設計の知識に基づく「あるべき配置」の草案です。前提は次の3点です。

- 現状の145件は見積数量を機械配置したたたき台であり、**現状配置にはとらわれず作り直す**。
- Claude Codeが一般知識の範囲で「必要な設備を必要な数だけ、あるべき位置に」置いた草案を作り、**最終調整は施主が手動で行う**。
- 施主固有の生活動線・採用家電は未ヒアリング。草案の前提と代替案は各項目の `note` と本書8章に残す。

本書は監査（1〜3章）と草案（4〜8章）で構成し、草案はまだ `data/electrical.json` に反映していません。反映手順は9章です。

---

## 1. 結論

1. **現状配置は「作り直し」が妥当です。** 壁付け95件のうち29件（31%）がドアや窓の開口と物理的に重なり、自宅LDK（32.7㎡）の照明が3灯しかない、IH専用コンセントがキッチンから3.2m離れている、民泊棟にAC専用コンセントが1つも無い等、機械配置ゆえの不自然さが多数あります（2章）。
2. **草案は199件です。** 見積154箇所に対し、照明+16、一般コンセント+18（専用コンセントとの合計では+7）、片切スイッチ+1、それ以外は見積と同数です。加えて見積に無い型（LANコンセント10・エアコンスリーブ6・換気扇5）を、実際に工事で必要になるものとして置きました（5章）。
3. **草案は幾何的に検証済みです。** 全件が壁の実在範囲内にあり、ドア・窓の開口と重ならず、部屋の帰属が意図どおりであることを機械確認しました。家具の裏に隠れる23件はすべて意図的なもの（TV裏・冷蔵庫上・デスク裏等）です（6章）。
4. **精度の自己評価**：幾何整合は高、一般ルールの適用は中〜高、施主固有の最適解は低〜中です。特にエアコンの位置（外壁が限られる）、スイッチの取っ手側（建具の吊元が暫定）、キッチン家電の内訳は施主・施工会社の確認が要ります（8章）。

## 8. 施主に確認したい前提（草案で仮置きしたもの）

1. **エアコン**：自宅LDK（20畳）に1台で足りるか。2台目なら南壁x≒13.2（キッチン上）が候補。民泊LDKのエアコンは現家具の西壁（内壁）から南壁へ移した。
2. **キッチンの向き**：両キッチンとも作業通路が東側という現在の幾何を前提にした。対面キッチンにするなら自宅LDKのコンセント（カップボード上）とIHの位置が変わる。
3. **3路の組み合わせ**：3章の8組で良いか。2F廊下（組8）は人感センサーへの置換も可。
4. **民泊のTV**：洋室のTV端子は西壁に仮置きしたが、ベッドから見やすい壁が無い。不要なら子供部屋1等へ振り替え。
5. **情報機器**：ルーターをSC（分電盤脇）に集約し、各室へLANを引く前提。無線のみなら10件のLANは不要。
6. **屋外**：EV充電（200V専用）、エコキュート・給湯器の電源、宅配ボックス電源、スマートロック（民泊）は未配置。防水コンセント3件は汎用。
7. **建具の吊元**：スイッチは「ドア脇の壁が広い側」に置いた。吊元が確定したら取っ手側へ寄せる。
8. **見積の数え方**：5章の差分を施工会社に確認する際、「電灯配線」「専用コンセント」の定義を聞く。

## 9. 反映手順（次のステップ、未実施）

1. ブランチを切る（`electrical-replan` 等）。理由：145件の全面置換は `validate_electrical.py` で機械検証できるものの、施主が旧配置と見比べたり戻したりできる単位で残す価値があるため。AGENTS.mdの基準では「既存の仕組みに乗ったデータ調整」に当たりますが、規模を踏まえブランチを推奨します。
2. `build/electrical-replan/plan_electrical.json` を `data/electrical.json` へ書き込み、`node scripts/build-web-data.mjs` → `python tests/validate_electrical.py` → `python -m pytest tests/test_electrical_assets.py tests/test_lighting.py` を通す。
3. 俯瞰モードの部屋フォーカスで、施主が1部屋ずつ確認・手動調整する。
4. UE側：照明の器具IDは維持しているので `lighting-settings.json` のグループはそのまま解決するはずですが、追加した器具は既存グループに属さないため、必要なら民泊LDKのグループ（`guest-ldk-main` 等）へ追加する。完全refreshで実機確認する。
5. 施主が8章の前提を確定したら、該当箇所を修正して `status` を `derived`/`verified` に上げる。
