# W05 採光条件と日時比較の実用化 — 事前計画

状態：詳細化済み。W04受入後の確認で一括実装と判断しました。[確定したW05仕様](W05-daylight.md)を実装指示として使用してください。以下は事前計画の記録です。

## 到達する成果

ゲストLDKで季節・時刻を選び、実敷地に対する日差しの入り方を、同じ視点・仕上げ・露出で比較して保存できます。設定に根拠と確度を付け、未確認の入力がどれか利用者にも分かります。W04の材質品質・面別設定は維持します。

## 既存の土台

unreal/solar_position.pyの日時・位置・真北からの太陽角度計算、sun-cases、site_context.pyの周辺遮蔽、比較撮影と状態保存が既にあります。新しい太陽計算を一から作るタスクではありません。現在のサンプル地点の動作確認と、実敷地条件で使える状態を区別します。

参照：VISUAL_TWIN_PLAN.mdの日時比較、MATERIAL_SITE_STUDY.md、COMPARISON_GALLERY.md、unreal/solar_position.py、unreal/site_context.py、unreal/study_controls.py、scripts/refresh_inputs.py。

## まとめて実装する範囲

1. ローカルの敷地設定を整理し、緯度・経度・真北補正・時差・情報源・確度を扱います。住所/位置や個人資料は公開Gitへ入れません。既存ローカル設定を利用し、二つ目の正本を作りません。
2. 現在の真北補正とモデル座標の意味をUI/図で示し、日時選択を簡単にします。春秋・夏・冬の代表日、午前/正午/午後を選択できます。既存の範囲外太陽条件は理由付きで案内し、夜間照明はW06へつなぎます。
3. 日影へ効く窓の位置・有効開口・庇/屋根・主要な周辺遮蔽を棚卸しし、必要な概形を接続します。全外構の精密モデル化は行いません。ガラスの現在の影/透過近似を明示します。
4. 比較中は視点・画角・露出・仕上げを固定して日時だけを変え、案名と日時を画面/出力へ表示します。自動露出で差が隠れないようにします。太陽角度・光源強度・露出を混同せず記録します。
5. 日時・敷地/遮蔽入力の対応を名前付き案、内覧保存、再生成、代表比較画像まで引き継ぎます。違うcontextの案を無断で現在条件へ読み替えません。

## 入力と未確定時の扱い

着手時に既存ローカル資料を確認し、足りない真北/位置/周辺寸法だけを施主へまとめて確認します。施主回答待ちでも入力UIとサンプル検証は進められます。実敷地が未確認なら「仮条件で使用可能・実敷地適用待ち」と記録し、現地条件確認済みとはしません。確認できない周辺建物を実在のものとして作りません。

屋根等の欠落がLDKの日影を大きく変える場合、その必要最小限の形状をこの段階で直すか、W07から前倒しするかを判断します。建物の寸法はhouse.json等の既存正本に修正根拠を残します。

## 完了条件・軽い検証

- 代表的な2日時で日差し方向が変わり、固定条件と使用入力が確認できます。
- 代表的な遮蔽物の有無で期待する影の差が出ます。
- 案保存→再読込/再生成で日時・context・面別仕上げが維持されます。既存W04との往復を1回まとめて確認します。
- 不足する真北設定または不一致contextを1例案内します。
- 実敷地入力がある場合は方位と代表日時を独立に照合します。入力待ちは受入記録に残します。

Lumen画像から実照度(lux)を保証する計測機能や、年間日射の網羅解析、天候の物理的校正は今回の完了条件ではありません。これは採光の視覚比較です。

## W04受入後の判断事項

W04のA/B条件固定・context検証・状態形式が実際に揃ったか、ローカル資料が揃うか、日影へ効く形状が欠けていないかを確認します。原則一括です。実敷地情報だけが長期待ちなら「機能実装」と「現地入力確認」を分ける選択肢があります。機械的にA/B/Cへ分割しません。

規模見込み：中。主な不確定要素は実敷地入力と日影形状です。成果物は操作手順、入力/確度一覧、代表比較、W05-reportとレビュー束です。
