## 日常利用

入口はトップの `interior-launcher.cmd`、全館モデルは `build/W08-F-delivery/ue` です。ローカル設定は全館モデルと「自宅入口」を選択済みです。「前回の続き」「ゲスト入口」へ変更できます。既存ゲストモデルも一覧から選択できます。機械固有のエンジン/Blender/cache設定と登録済みモデルを維持し、切替前設定を `build/W08-F-evidence/config-before.json` に保存しました。

[日常操作ガイド](../DAILY_USE.md)に、家具編集→JSON取込→全館更新→内覧→案保存・比較の手順、保存先、失敗時の戻し方をまとめました。旧 `guest-launcher.cmd` は同じ機能を開く互換入口として残しています。

## 実装内容

- ランチャーのモデル判定をguest/home/wholeへ拡張し、範囲を表示します。更新は元モデルの範囲を維持し、出力範囲の一致を含む成功確認後だけ切り替えます。
- 全館モデルの内覧開始位置を選べます。UEで通常の保存復帰を行った後、安全な入口へ移動します。室別仕上げ・照明・扉は維持し、F5までは保存ファイルを書き換えません。旧モデルは再生成まで「前回の続き」のみです。
- トップのThree.js家具編集へのボタンを追加しました。家具取込は全館正本に作用します。内覧/エディタ、更新、家具反映、案保存、比較撮影の競合実行を拒否します。
- A/Bの検証を階・太陽来歴・光量・各室の面上書き/器具へ拡張しました。対象室variant以外が変わる撮影は受理しません。
- 実GUI構築で発見した既存の `ChooseModelWindow._register` とTk内部メソッドの衝突を修正しました。
- バックアップ復元時にWeb生成データも再生成します。従来は正本だけ戻り、次の更新が生成データ不一致で停止する場合がありました。子PythonをUTF-8モードで起動し、日本語ログの文字化けも修正しました。
