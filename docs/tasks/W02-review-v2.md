## 必須修正A / 高：置換途中の失敗で旧保存が失われる

対象：Walkthrough.cpp:217（SaveView）。成功判定の修正は正しいですが、保存保護そのものは未完了です。

ローカルEngine/Source/Runtime/Core/Private/HAL/FileManagerGeneric.cpp:299以降を確認しました。FFileManagerGeneric::MoveはReplace=trueのとき、既存DestをDeleteFileで削除し、その後MoveFile(Dest,Src)を実行します。MoveFileが失敗し再試行も失敗すれば、旧保存を削除したままfalseになります。

今回の読み取り専用試験は最初のDeleteFileに失敗するケースです。そのケースで旧保存が残ることは、DeleteFile成功後の失敗に対する保護を証明しません。これはソースから確認した失敗経路であり、施主のファイルを破壊して再現したという意味ではありません。

修正契約：新JSONを完成させてから、旧保存を事前削除しない置換方法を選択してください。Windowsの対象API/UEの利用可能な機構の実装と失敗保証を確認し、必要なら旧ファイルの回復可能なバックアップを保持する設計にしてください。単に同じMoveへ置き換えるラッパーでは解消しません。初回保存（旧保存なし）、通常上書き、temp書込み失敗、置換処理失敗を分けます。エラー時は旧データが元パスまたは明示的な復旧経路に保持され、成功と表示しないこと。停電耐性を今回の追加要件にはしません。

検証：専用ファイルと限定された障害注入で「temp完成後、置換が失敗する」経路を再現し、旧データの前後ハッシュとF9/再起動の復元を確認してください。成功したtemp書込みの試験だけで代用せず、実際のネイティブ保存関数を通す回帰テストを残します。ユーザーデータは使いません。
