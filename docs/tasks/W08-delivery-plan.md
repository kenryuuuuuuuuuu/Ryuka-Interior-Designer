# W08 日常利用への仕上げと初期版の引渡し — 事前計画

2026-09-09追記：[段階実装設計](W07-staged-design.md)では、ゲスト完成後にW08-Gとして本書の操作入口を先行し、全館完成後はW08-Fとして拡張確認する案を推奨しています。順序は施主承認済みです。

## 到達する成果

施主が毎回AIへ操作を依頼しなくても、Three.jsで編集した内容を正本へ取り込み、再生成し、UEで内覧・比較・記録できる初期版を完成させます。W08の受入を今回の仕組みづくりの終点とします。

## まとめて実装する範囲

1. 現在の複数CLI/生成物の場所を整理し、入口画面またはランチャーから最新モデル・比較案・更新結果を開けるようにします。見つけにくいbuild配下のパスを毎回探す操作を減らします。既存refresh/indexを利用できるなら新アプリを一から作りません。
2. Three.jsのローカル保存と共有JSONの違いを画面で明示し、書出し→正本取込→差分確認→再生成を案内します。取込時には既存validatorを使い、寸法/確度情報を落としません。ブラウザ内の変更を未反映のまま「更新済み」と表示しません。
3. 家具の代表的な移動/寸法変更/追加を通して、配置・アセット対応・仕上げ・照明の保持を確認します。対応していない新家具型は必要なアセット対応を案内します。あらゆるThree.jsコード変更の自動移植を保証しません。
4. 長い生成工程の進捗、失敗理由、最後に成功したモデル、保存済み案、復帰手順を見えるようにします。失敗した出力を完成扱いにせず、手動のバックアップや復元方法を短く文書化します。
5. 比較画像に案名・視点/日時・露出・点灯・仮仕様を付けて、施主や施工会社との検討に使える記録を保存します。公開共有用出力に敷地情報・絶対パス等を含めない選択を用意します。自動公開はしません。
6. 参考LDK画像と代表UE視点を見比べ、既存の素材品質を維持できているか、色・光・距離感を判断できるかを施主と確認します。材質の消失・光漏れ・目立つ形状欠落など判断を妨げる不具合を修正します。植物/布の細部や全室の写真同等化を際限なく追加しません。

## 完了条件

施主向け手順で「家具変更→正本保存→差分確認→再生成→全館内覧→仕上げ/日時/点灯案比較→記録」を代表1回通せます。再起動後も案を見つけられ、入力不足/生成失敗時に次の操作が分かります。施主が確認した画質・操作環境と、残る未確定仕様を引渡し記録へ残します。

ゲストLDKの最終的な見栄えは施主確認が必要です。「参考画像と同じクオリティを達成」とテスト数だけで判定しません。仕組み完成と、採用品番確定後のデータ調整を区別します。

## 初期版に含めないこと

UE不要の配布exe、Web/スマホで同品質の内覧、VR、クラウド共同編集、実照度の保証、全家具の市販品完全再現は追加要望として扱います。これらが未実装でも、現在のWindows＋Blender＋UE環境で上記操作が成立すれば初期版は完成です。
