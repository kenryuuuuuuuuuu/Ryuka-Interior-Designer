## R1 高：doorStatesがエディタ・Blenderの葉へ適用されない

対象：`unreal/study_controls.py:210`付近、`blender/build_interior.py:544`付近、`unreal/import_study.py`。

apply_state()は扉IDを検証するだけで、葉のtransformを変更しません。コメントにも「editor scene never moves a door leaf itself」と明記されています。Blenderも閉状態の葉を生成し、開transformをbindingsへ記録するだけで、保存状態のdoorStatesを形状に適用していません。インポートは葉をMovableにしますが、初期開扉状態は反映しません。

例えば内覧でdoor-002を開けて保存し、エディタへ反映/完全refreshすると、JSONはopen=trueでもエディタとBlenderでは葉が閉じたままです。採光・仕上げ比較が保存条件と異なります。提出verify_w07_g2.pyも辞書の一致だけを確認しているため、15項目成功ではこの問題を検出できません。

閉/開の基準transformを共有し、Blender生成・UE初期インポート・apply_state/案読込が実際の葉にも同じ状態を適用してください。内覧が「起動時の位置＝閉位置」として引き戸の基準を採る現行方式も同時に見直し、開いた生成物をさらにずらさないようにします。エディタの専用トグルUI新設は不要ですが、保存状態の形状反映は必須です。

確認：open=trueの代表扉について、Blender・UEの実transformが期待値に一致すること。旧案通常読込で実際に閉じ、比較A/B/終了では実際の葉が開いたまま固定されること。転送JSONの一致だけで成功にしません。

## R2 高：視点変更後も古いwalkthrough.roomIdが残り、復帰先を誤る

対象：`unreal/study_controls.py:select_room/remember_view/scene_state`、`unreal/walkthrough/Source/RyukaInterior/Walkthrough.cpp:325`付近。

内覧由来のLDK保存を読み、エディタで洋室へ切替すると、cameraとactiveRoomIdは洋室になりますがwalkthrough.roomIdはLDKのままです。レビュー側で実select_room関数を抽出し、シーン適用だけを代替してこの不一致を再現しました。

C++ Restore()はこの古いroomIdを復帰対象へ採用し、洋室のカメラ位置をLDK内の安全地点へ補正してしまいます。profileId/levelは検証せず、未知室の場合も玄関へ落とします。またwalkthroughを解除するだけでは現行Restoreが常にEntryRoomIdを選ぶため、正しい視点復帰にはなりません。

エディタの視点変更時にwalkthroughを再解決または解除し、内覧復帰側もcamera・現在profile・実室/床から整合する帰属を解決してください。初回の「玄関から開始」と保存済み視点の復帰を区別します。不正なprofile/室/階を黙って玄関へ読み替えず拒否し、安全補正は解決済み同室内に限定します。既存の全室roomStates・扉・太陽条件を保持してください。

確認：LDKで内覧保存→エディタで洋室へ切替・保存→内覧開始/F9で洋室へ復帰する1例。未知profile/矛盾する帰属の拒否は軽量確認で十分です。

## R3 高：両開きの向きと開閉の干渉判定を修正する

対象：`unreal/circulation.py:double_swing_hinges_and_deltas`、C++ `FindNearestDoor/InteractDoor/ApplyConditions`。

提出door-bindings.jsonのdoor-024は左右の葉がともにopenYawDeltaDeg=-85です。左右の外端を蝶番とする葉に同符号を与えると、片方が収納側、もう片方が洋室側へ開きます。右葉は_swing_delta_degがhingeSideで既に反転しているのに、さらにsign=-1で反転しています。両葉が同じ側へ開く幾何へ修正してください。

InteractDoor()は先に葉を即時移動し、その後プレイヤー位置のSafe()だけを確認しています。葉の移動途中にあるカプセル、壁・家具との干渉は検査していません。FindNearestDoor()も距離と向きだけで、壁越しを遮る確認はありません。仕様で要求した「開閉で既存障害物に食い込まない」「移動領域も考慮」「壁越し操作をしない」は未実装です。

可動葉に適した衝突形状と移動領域の検査を用意し、始点/終点だけ安全でも障害物を通り抜ける動作は拒否します。引き戸の引き先も、既存壁へ葉を埋め込むだけで解決しないでください。候補の検査が通った後に状態と葉を更新し、拒否時は元の開閉状態を保ちます。近距離の遮蔽確認も追加します。物理シミュレーションや滑らかなアニメーションは不要です。

確認は代表の干渉拒否1件と両開き1件へ絞れます。既存の閉扉通行ブロック/開扉通過は維持します。
