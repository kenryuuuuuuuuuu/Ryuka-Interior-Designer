# W07 自宅・ゲスト・2階の全館内覧 — 事前計画

2026-09-09追記：[段階実装設計・ゲスト先行案](W07-staged-design.md)を作成しました。施主承認済みの順序はゲスト3単位→W08-G→自宅4単位→W08-Fです。以下は当初の一括案です。

状態：DRAFT。2026-09-09作成。W06受入時に現行形状を棚卸ししてREADYへ移します。

## 到達する成果

ゲストLDKだけの検討環境を、自宅側・廊下・階段・2階まで移動して確認できる家全体へ広げます。代表室で仕上げ/採光/照明を検討でき、部屋を越えても保存状態や面の所有関係が混ざらないようにします。

## 既存の土台

Three.jsには全館の部屋・階段/建具データがあり、Blender/UEは内覧に必要な形状や操作の一部が不足しています。既存の図面由来データを移植し、改めて間取りを推測し直しません。W02の安全な歩行、W03の識別、W04〜W06の比較を再利用します。

## まとめて実装する範囲

1. 部屋/階段/建具/屋根/床開口の「正本あり・生成未対応・根拠未確認」を棚卸しします。階段の踏面・蹴上・踊場、扉の開閉方式、妻壁等の欠落を確認し、内覧/日影へ必要なものから接続します。
2. 本来の壁や床を移動させず、階段の形状・衝突と1F↔2F移動を実現します。ドアを開いて通過できる代表操作を用意し、単に壁抜けにして通路を作りません。施工未確定の方式はestimatedのまま表示します。
3. 内覧対象の部屋制約を家全体へ拡張し、現在室/階、開始位置、保存位置、復帰条件を整理します。屋外や未完成領域を通過できたと誤認しない境界にします。
4. 必要な室の面IDを明示登録し、共有壁の両室側・階の重なり・斜辺の扱いを正しくします。W04レビューに残した「同じ共有壁の両側を登録すると最初の側しか処理されない」問題をここで解消します。床/天井もlevelと部屋を照合します。
5. roomId単一前提のstudy/比較状態を全館へ拡張し、旧ゲストLDK案を読み込めるようにします。自宅/2階の面編集と照明へ広げます。未登録部分・未対応器具を画面で明示します。
6. 施主PCで代表ルートを歩き、フレームレートと影/質感を確認して画質設定を整えます。まず通常の1080p内覧で30fps程度を実用目標とし、実測後に対象解像度と品質の組合せを合意します。全室の小物を高精細化することは要求しません。

## 必要な入力

階段・建具の確定仕様や未完成屋根の根拠を既存資料から優先取得します。資料不足の場合は仮定と利用制限を明示し、施主確認が必要な部分だけをまとめます。CADがないこと自体を全館内覧不可の理由にはしません。

## 完了条件・軽い検証

- ゲスト→自宅→階段→2階の代表ルートを実入力で歩き、床抜けや通行不能がありません。
- 自宅側の共有壁一面を変更してゲスト側が不変、上下階の同じ平面位置にある床/天井が混ざらないことを代表確認します。
- 代表的な2階位置で保存→再起動→復元し、再生成後も室/階・仕上げ・点灯が維持されます。
- 使えない保存位置を1件案内し、安全な復帰経路があることを確認します。全隅の移動や衝突の網羅テストは不要です。

## 着手時に見直すこと

残る計画の中で最も不確定幅が大きい段階です。階段/屋根の不足と全館状態形式を先に確認します。原則一括ですが、形状資料待ちが長い、または階段移動と全館データ移行を同時に変更すると原因を切り分けられない場合には、具体的理由を添えて分割を判断します。
