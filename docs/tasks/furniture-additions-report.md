# 小上がり・マットレス・作業用ソファテーブル

2026-09-12。BASE `db9a06f`、作業ブランチ `codex/furniture-platform-mattress-table`。

3種類をカタログとThree.js描画へ追加しました。平面図の家具編集に種類・部屋選択と追加/取り消しを設け、ブラウザ保存と既存JSON書出しへ接続しました。追加家具が正本へ取り込まれた後は同じIDを二重復元しません。移動後の書出しでは所属室を座標から更新し、室外配置を拒否します。

Blenderは種類から木製台2部品、マットレス3部品、片側支柱のテーブル3部品を生成します。個別IDのasset-binding追記は不要です。幅・奥行・高さ・回転・床上高さを既存経路で反映します。仕上げ材質は所属室のwood/fabric/frameを使用します。新形状は推定仕様です。

検証：239件のPythonテスト、実Three.jsライブラリを使った形状・追加・保存・書出し・室外拒否・取り消しテスト、4種validatorとWeb生成チェックが成功しました。全館の検証専用配置でBlender生成・GLB往復・UE取込・状態転送まで成功しました（`build/furniture-additions-ue-v2`）。Blender実データで8部品の家具ID、外形高さ、マットレス底面が2階床+0.30mであることも確認しました。最初の検証配置は室外の中心座標を指定していたため生成で拒否され、室内へ修正して再実行しました。

家具正本は試験終了後に元のバイト列へ復元し、日常用ランチャーの現行モデルは変更していません。任意の部屋への追加は施主がThree.jsで行います。更新後のUEモデルにはその配置が反映されます。操作手順は[DAILY_USE](../DAILY_USE.md)を参照してください。ローカル証跡は `build/furniture-additions-evidence/` に保存しています。
