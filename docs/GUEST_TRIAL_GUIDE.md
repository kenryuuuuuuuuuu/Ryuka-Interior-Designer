# ゲスト試用ガイド（最短）

ゲスト8区画（玄関・ホール・LDK・洋室・トイレ・洗面脱衣・UB・収納）の内装を、
コマンドやパスを毎回入力せずに「開く → 家具変更を取り込む → 更新する →
案を保存する → 比較を記録する」まで操作するための入口です。

対象は Windows ＋ Blender ＋ Unreal Engine の現在の環境です。UE不要の配布版・
全館・階段・クラウド公開・採用品の精密モデルは対象外です。

---

## 1. 起動

`guest-launcher.cmd` をダブルクリックします（このワークツリーの直下にあります）。
どのフォルダから起動しても、パスはこのワークツリーを基準に解決されます。

初回は依存の場所を確認します。「設定」で次を指定してください（`build/launcher/config.json`
に保存され、git には含まれません）。

- Unreal Engine のフォルダ（例：`C:\Program Files\Epic Games\UE_5.8`）
- `blender.exe`
- DDC cache のフォルダ（119文字以内。例：`C:\UE_DDC\w08g`）

次に「モデルを選ぶ」で、生成済みの guest プロジェクトを1つ登録します。候補は
scope が guest か・取込が成功しているか・内覧が構築されているかを確認して表示します。
日付やフォルダ名だけでは判定しません。登録すると再起動後も選択と案が復元されます。

---

## 2. 内覧・編集・保存

**「内覧を開く」** … 描画付きの内覧が別ウィンドウで開きます（テスト用のsmokeや
初期化スクリプトではありません）。操作キー：

| キー | 動作 |
|---|---|
| WASD | 歩く |
| マウス | 見回す |
| Tab | カーソル表示（メニュー操作） |
| 1 / 2 / 3 | 対象室の仕上げ切替（**編集対象の室のみ**。玄関等は対象外表示になります） |
| 4 / 5 | 太陽高度（手動角度・**未校正**） |
| E | 近くの扉の開閉 |
| F5 | 今の仕上げ・視点・扉・太陽条件を**このモデルに保存** |
| F9 | 最後に保存した状態へ復元 |

**保存してから閉じる**こと。閉じずに更新を始めないでください。内覧のF5保存は
基準状態で上書きされません。

**「編集・比較を開く」** … UEエディタでプロジェクトを開きます。面編集や詳細な
A/B比較は、エディタの『ツール → 内装比較』から行います。ランチャーへは
再実装していません。ここでも**保存してから閉じて**ください。

---

## 3. 家具変更の取り込み

ブラウザの内装モデル（`interior-white-model.html`）で家具を動かし、
**「⬇ furniture.jsonを書き出す」** で保存したファイルだけを取り込めます。
house / 電気 / 建具の JSON は取り込めません。

1. **「家具JSON取込」** でそのファイルを選ぶ
2. 現行の正本との差分が全件表示されます（全館の書出しなので**ゲスト外の変更も表示**、
   削除件数・note/status が消える項目も表示）
3. 既存の検証（ID重複・未知の型・不正な寸法/室参照・階の食い違い・asset-binding
   との不整合）に通れば **「正本へ反映」** が押せます
4. 反映すると `data/furniture.json` を置換し、Web生成データを再生成します。
   反映前に直前の正本を `build/launcher/backups/` に控えます

**取り込み ≠ UEへの反映**です。UEへ反映するには次の「モデル更新」が要ります。
ブラウザ内保存 / ダウンロードしたJSON / リポジトリの正本 / 生成済みUEモデルは、
それぞれ別の状態です。

---

## 4. モデル更新

**「モデル更新」** … 選択モデルの生成入力と現在の正本の差分を表示し、
**「更新開始」** で既存の再生成（Blender → UE → 内覧構築 → 転送検証）を1回実行します。

- 前のモデルと保存済みの案は**上書き・削除しません**（新しい出力フォルダ `build/W08-G-update-…` を作ります）
- 工程名・実行中/成功/失敗・経過秒・ログを表示します（根拠のない進捗率は出しません）
- 終了コード0・`status: complete`・取込/転送/内覧構築の成功を確認してから、
  現行モデルを新モデルへ切り替えます
- 失敗したら工程名・理由・ログを表示し、**前のモデルと案を維持**します。
  修正後に再試行するか、前のモデルで続けられます

更新の前に内覧・エディタを**保存して閉じて**ください。同じモデルを起動中に
更新は始められません（二重起動も防ぎます）。

---

## 5. 案の保存と比較記録

**「案と比較記録」 → 「保存した案」**

- 「現在の保存を案にする」で、名前・メモを付けて現在の保存状態を案として残せます。
  保存元は **F5／エディタの最新の有効な保存** を既存の共通処理が選びます
  （未保存の画面状態は案にできません）。既存の案は黙って上書きしません
- 案の読込・比較は、内覧を「編集・比較」で開いてエディタの『ツール → 内装比較』から
  「案の読込」「比較A」「比較B」を選びます

**「案と比較記録」 → 「比較記録（仕上げA/B）」**

- 「仕上げA/Bを記録」で、対象室の仕上げ違い（natural / warm）を固定カメラで撮影し、
  画像と**その画像を生成した条件**（案名・対象室・視点・日時または手動太陽・露出・
  昼夜/点灯・仮仕様）を対応付けてローカルに残します。撮影失敗は登録しません。
  比較元の案・モデル状態は変更しません
- 「共有用コピーを作る」で、画像と必要な比較条件だけのフォルダを出力します。
  絶対パス・敷地座標・ローカル設定・生ログ・元データJSONは含めません。
  **自動公開・送信はしません**

---

## 6. うまくいかないとき

- **依存が見つからない**：状態表示に不足箇所が出ます。「設定」でエンジン/Blender/cache
  を指定し直してください
- **内覧が開けない**：内覧が構築されていないモデルです。「モデル更新」するか別のモデルを選びます
- **更新が失敗した**：表示された工程名・理由・ログ（`build/launcher/logs/` と
  `build/W08-G-update-…/`）を確認します。前のモデルは維持されています。「モデルを選ぶ」で
  前のモデルへ戻せます
- **中断・再起動で結果が不明なジョブ**：成功として扱いません。出力フォルダの
  `refresh.json` の `status` と `ue/import-verification.json` を確認してください

---

## 7. 既知の制限（W07-G3から引き継ぎ）

- **洗濯機の向き**：`fur-002` は正本 `rotation: 0` で、丸ドアがUB側の壁を向きます。
  室内の代表視点からドア正面は見えません。設置向きは推測で変えていません（配置レビューの残件）
- **狭所**：トイレ・UB・収納・玄関・ホールは実寸が狭く、単一の室内視点では画角が窮屈です。
  内覧では入口からの確認になります（壁抜けは通行ではありません）
- **仮仕様**：仕上げ・照明・採光は未校正の仮条件です。実敷地の位置・真北・採用品番は
  確認待ちです。写真同等の品質ではありません
