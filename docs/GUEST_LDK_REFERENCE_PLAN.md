## 目標と前提

施主が提示した生成画像2枚（リビング①・②）の、明るい木、暖色の淡い壁、石・タイル調の床、布と編み地、柔らかい自然光を参考に、実際の建物形状に沿ったゲストLDKを歩けるようにします。画像どおりの家具購入や建築仕様は確定していません。

- 建物・窓・天井の形は既存の正本と図面を優先します。画像の梁や外の風景を建築・敷地の事実として追加しません。
- 画像2枚の形状・配置が完全に整合するとは限りません。画像から実寸を確定せず、仮寸法には `estimated` と根拠を記録します。
- 参考画像の原本はローカル参照のみとし、この文書に個人情報を含むパスを記載しません。
- 既存案を基準として残し、変更差分を確認できる単位で作業します。配置案の切り替え機能は現在未実装です。初期はGit差分で変更を追跡し、複数配置案が必要になった段階で別途設計します。

## 現在の入口と責任分担

正本JSONからThree.js表示とBlender生成へ分岐し、Blenderの生成物をUnrealへ取り込みます。Three.jsの画面操作は必須ではなく、開発者が正本を直接更新して両方へ反映できます。ブラウザの下書きはJSONを書き出して取り込むまで後段へ反映されません。

| 管理対象 | 保存先・扱い |
|---|---|
| 家具の種類・寸法・位置・向き | 既存 `data/furniture-catalog.json` と `data/furniture.json`。Three.jsとBlenderで共有 |
| 家具を床から浮かせる高さ | 現行家具契約にないため追加設計が必要。家具本体の `heightOverride` と分ける |
| 建物・開口部・電気設備 | それぞれの既存正本を維持。家電本体とコンセントを同じオブジェクトにしない |
| 家具の詳細モデル | 家具IDからモデルへの対応を追加予定。位置を別途二重管理しない |
| 壁・床・天井・家具の素材 | 見た目の設定。現在の共通パレットから、必要な部屋・家具単位の割当へ拡張予定 |
| 花瓶・本・クッションなど | 親家具に対する相対配置などで再生成可能にする案。現在未実装 |

現在の一括更新で引き継げるのは対応済みの仕上げ・視点・太陽・周辺設定です。Unrealへ手で追加した任意の家具や材質編集をすべて引き継ぐ機能ではありません。

## 足りない要素

以下の仮寸法は、制作開始時の提案値です。画像の測定値・製品仕様・施工条件ではありません。実装時に配置と干渉を確認して初めて正本へ登録します。

| 要素 | 現状と最初の対応 | 仮寸法・必要な情報 |
|---|---|---|
| テレビ本体 | 型も配置もない。最初の追加対象。画面と筐体を分けた簡易模型を両方に実装 | 外形1.12×0.06×0.65m案。画面の16:9と外形を区別。底面の床上高さを別指定 |
| エアコン本体 | 家具カタログにない。電源設備の有無と本体の有無は別 | 外形0.80×0.25×0.30m案。設置高さ、配管、窓・天井との関係は未確定 |
| レンジフード | キッチンの詳細化に未対応。キッチンに追従する部品にする候補 | 幅0.60m案。下端高さ・排気経路・製品寸法は未確定 |
| 水栓 | 現在のシンク詳細に追加が必要 | キッチン内の相対位置で生成。外形・操作空間を確認 |
| ラグ | 未登録。室内演出用の薄い形状を追加予定 | まず1.60×1.20m案。ソファ・机・歩行範囲に合わせる |
| ロールスクリーン | 未対応。窓IDに紐付けて生成する候補 | 幅・取付位置は実際の窓から。開き量と透過性を設定する必要あり |
| 壁の円形格子装飾・棚 | 未対応。後半の意匠検討 | 大きさ・取付高さは配置確認後。構造梁とは別の装飾扱い |
| クッション・ブランケット | ソファの基本形状はあるが画像相当の布表現はない | 親ソファの寸法に追従する詳細部品 |
| 花瓶・植物・本など | 未対応 | 親家具・棚に相対配置。ライセンスと再生成元を記録 |
| ダウンライト | 電気計画に既存データあり。画像の灯数をそのまま追加しない | 対象室の配置・器具表現・発光の対応を個別照合 |

## 仕上げの差分

| 面・条件 | 現状 | 参考案で必要な作業 |
|---|---|---|
| 床 | UEで仮の木フローリング | 淡い石・タイル調の案を追加。目地・寸法・反射を設定 |
| 壁 | 仮パレットと表面模様 | 暖色の淡い壁、細かな凹凸と粗さを調整。塗り壁か壁紙かは未確定 |
| 天井 | 生成済み勾配形状と仮素材 | 木板の幅・方向・継ぎ目を調整。天井形状は画像で置換しない |
| 梁 | 画像に露出梁がある | 施工上の存在と位置が未確認のため、建物正本への追加は保留 |
| 自然光・外景 | 太陽条件の比較と仮の周辺条件 | 見栄え検証は仮条件を明示。実敷地の採光判断には所在地・真北・周辺条件の確認が必要 |

## 実装順序と完了条件

| 順序 | 作業単位 | 完了と判断する成果物 |
|---|---|---|
| A：今回 | 差分棚卸しと責任分担 | この対応表。正本や画像を変更しない |
| B：次の実装 | テレビ＋家具の設置高さ | 床上高さを省略した既存家具は表示不変。テレビの寸法・位置・高さがWeb/Blender/UEで一致し、ブラウザ書出しでも保持される |
| C | 詳細モデルの対応付けを少数で実証 | 既存ソファ等1点で詳細形状を割当。移動・回転・寸法変更・削除後の再生成で二重配置や取り残しがない。対応不能な寸法は明示 |
| D | 主要家具と設備の配置をそろえる | 円卓、必要な椅子、エアコン、フード等。机・椅子の使用域、出入口、窓との干渉を簡易模型でレビュー |
| E | 一室の質感を仕上げる | 実建物に沿った2方向のレンダー。床・壁・天井・家具・小物を再生成可能な設定で管理 |
| F | ウォークスルー | ゲストLDKの歩行操作・壁や家具の衝突判定、実機での描画速度を確認。歩行体験から配置と仕上げを修正 |

Bでは家具の設置高さを電気設備の設置高さと混同しません。データ契約、検証、Web描画・編集・書出し、Blender配置、内覧時の家具当たり判定への影響をまとめて扱います。床上のテレビを作るために、本体高さを床からの総高さに見せかける方法は取りません。

Cでは「パラメータから組み直すモデル」と「寸法固定の製品モデル」を区別します。製品モデルをXYZ別倍率で引き伸ばして一致したことにはしません。モデルID、適用先家具ID、寸法の扱い、素材参照、出典・利用条件を保存する仕組みを作ります。

全室の家具追加、配置案切替UI、UEから共通配置への逆同期、任意の手編集の自動保存は、この一室の初回完成に含めません。Three.jsを使う既存作業を継続できるよう、挙動変更は専用ブランチで検証してから統合します。
