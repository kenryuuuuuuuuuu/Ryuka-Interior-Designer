## 未解決事項・要確認事項

### 施工会社に確認が必要（最優先）

1. **天井高**（現在2,400mm、全室一律の推測値。断面図がなく確認手段がない。立面図の階高実測値との整合は確認済みで矛盾はないが、天井下地の実寸が不明なため`estimated`のまま）
2. **室内ドアの実際の高さ**（Blender生成時は2.0mの仮値。建具表の実データ未反映）
3. 用途変更リスク（建築基準法・消防法、民泊転用時）
4. 水道メーター分離
5. 各棟へのLAN配管ルーティング
6. 「小屋裏まで張り上げ」壁が、防音壁（民泊-自宅境界）以外にも存在するか（1階平面図の注記を追跡した限りでは防音壁1箇所のみを指しているように見えるが、平面図全体を網羅的に確認したわけではない）

### リポジトリ・データ設計上の未解決事項

1. `rooms`/`walls`の自動同期化（現状は`rooms`を編集しても`walls`は手動で見直す必要がある。[ARCHITECTURE.md](ARCHITECTURE.md)の「rooms / walls について」参照）
2. Three.js vs Blenderのどちらで最終的な質感を作り込むか（未決定）
3. `web/`ディレクトリへの本格的なビューア分離（未着手。当面は`interior-white-model.html`内にThree.jsロジックを維持する）
4. この開発環境にBlenderが未インストールのため、`blender/build_house.py`の実行確認・`.blend`の再生成ができていない（2026-08-14時点、fl1/fl2修正・屋根追加後の再生成が必要）
5. 2F切妻屋根の東西妻壁（屋根下を塞ぐ三角壁）、および`Ryuka-Landscape-Designer`が持つ南東部A4上の下屋（`docs/MODEL-SPEC.md`§3.4.3）は未移植
6. 内覧モードは階段による1F↔2F移動を再現していない（階を跨ぐにはスポーン地点を選び直す必要がある）。壁の当たり判定は概算の壁厚データから導出したもので実測値ではない
7. 内覧モードの視点操作はドラッグのみ（Pointer Lock APIは未使用）。デスクトップでのマウス感度など、実機での操作感の調整はまだしていない
8. Web UI編集の位置・サイズはlocalStorageにしか自動保存されない。書き出し忘れると別端末・別ブラウザには残らない（`Ryuka-Landscape-Designer`と同じ制約。詳細は[BACKGROUND.md 5章](BACKGROUND.md#5-変更履歴ログ)）
9. 家具・設備には当たり判定・クリアランス表示がない。「実際に通れるか」の検証はまだできない
10. 造作（キッチン・洗面台・UB・便器）の寸法は日本の住宅設備の一般的な標準値であり、施工会社が採用する実機種の寸法ではない
